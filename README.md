# AI 空间数据评测：72 组对照测试

**结论**：大模型在「查得到」的空间任务上可靠（加权正确率 72%~100%），
在「必须算」的任务上系统性失效（22%~39%），而且失效方式是给出**看起来很精确、实际错上百公里**的答案，用户无从察觉。

> 测试对象：文心一言 / 豆包 / DeepSeek　｜　8 个空间任务 × 3 种问法 × 3 个产品 = 72 组　｜　2026.11

---

## 一、为什么做这个

坐标、方位角、投影坐标这类结果有个特点：**格式正确、数字合理、还带小数位，但可能是错的**。
用户没有能力验算，一旦进入选址、导航、工程测量等下游，错误会被直接放大成实际损失。

我做了一件很简单的事：**用测绘公式把每一家的答案重新算一遍**，看它能不能自圆其说。

---

## 二、测试设计

| 题号 | 任务 | 性质 | 标准答案来源 |
|---|---|---|---|
| Q1 | 哈尔滨西站经纬度 | 检索 | 维基 / Mapcarta / GeoNames 交叉印证 |
| Q2 | 黑龙江省会城市坐标 | 检索 | 市中心 vs 江北的落点判断 |
| Q3 | 哈尔滨—齐齐哈尔直线距离 | 半查半算 | 高德测距实测 267.6 km |
| Q4 | 罗定市龙岩村行政区归属 | 检索 | 区划代码 445381100214 拆解 |
| Q5 | 合法 GeoJSON 示例 | 规范 | RFC 7946 + 离线校验器 |
| Q6 | 广州市中心投影坐标 | 计算 | 高斯正算双算法复算 |
| Q7 | 罗定→北京方位角 | 计算 | 球面 12.33° / Vincenty 12.39° |
| Q8 | 写代码查 5 km 内小学 | 工程细节 | 高德 POI 码表 + v3/v5 参数表 |

三种问法构成控制变量：**A 直接问**（基线）、**B 加角色**（测「角色提示是否有效」）、**C 要求验证**（测「被要求解释时的表现」）。

判定分三级（正确 / 部分正确 / 错误，部分正确按 0.5 计入加权），数值题设容差：距离 ±5%、投影坐标 ΔY 以 0.5 km / 5 km 分档、方位角以 0.5° / 5° 分档。

## 三、核心发现

### 3.1 查 vs 算的断层

| 题号 | 任务 | 性质 | 加权正确率 |
|---|---|---|---|
| Q4 | 地名归属 | 检索 | **100.0%** |
| Q5 | GeoJSON | 规范 | **100.0%** |
| Q3 | 两点距离 | 半查半算 | 83.3% |
| Q1 | 单点坐标 | 检索 | 72.2% |
| Q2 | 城市坐标 | 半查半算 | 61.1% |
| Q8 | 写代码查 POI | 工程细节 | 55.6% |
| Q7 | 方位角 | 计算 | **38.9%** |
| Q6 | 投影坐标 | 计算 | **22.2%** |

整体：正确 38 / 部分正确 20 / 错误 14，**加权正确率 66.7%**。

### 3.2 三条反直觉结论

**① 加了「专业要求」，答案反而更差**

方位角题，直接问时豆包给 12°（标准 12.3°，基本对）；改成「请说明算法与椭球参数」后，豆包给 20.14°、文心给 20.3°——两个不同产品同时掉到同一个错误值上。
投影坐标题同理：DeepSeek 前两次正确拒答（「这个没有唯一公开值」），被要求必须给出 EPSG 与投影参数后，给了一个错 63 km 的数。

> 提示词里的「专业要求」不提升正确率，它让模型从「估算」切换到「编造推导」，而且编得更像真的。

**② 精确到小数点后两位 ≠ 精准**

把每家自己报的经纬度代回它自己报的投影参数复算，7 个给了数值的答案**全部偏差**：最准差 1.5 km，最差差 161 km——但都精确到小数点后两位。
在用户眼里，置信度和准确率是同一件事。

**③ 错误会在产品之间「传染」**

高德 POI 分类码 `141203` 是小学、`141201` 是高等院校。9 个回答里有 3 个把 `141201` 当小学用（DeepSeek 1 次、豆包 2 次），唯一写对 `141203` 的只有 1 条。
这不是随机错误，是同一个错误认知被多家共享——单测一家看不出来，横向比对才暴露。

## 五、方法可信度

- 所有数值结论**可用公式复算**，不是主观打分；
- 判定基准来自**测绘公式、官方区划代码、POI 分类码表**，不依赖任何模型输出；
- 投影坐标用三条独立路径交叉验证（Snyder 级数 / Karney 精确级数，两者差 0.0000 m / 数值反算还原）；
- 原图截图留存于作者本地，未上传（画面含平台账号信息）。

## 六、局限

样本 72 组、单一领域（空间位置），不能外推到模型整体能力；自建问题集，未接入真实用户 Session；
三款产品均为网页公开版本、版本号未逐一锁定；判定由作者一人完成，虽有容差与复算支撑，仍有主观空间。

## 附：界面改进建议

针对「计算类失效」提出三条，配一张原型（见 `prototype.png`）：

1. **输入侧**：坐标/投影类问题增加「坐标系」选择，默认 WGS84，可切 GCJ-02 / CGCS2000；
2. **输出侧**：输出坐标时强制附带坐标系标签 + 量级校验，异常就标红；
3. **能力侧**：把「算」交给确定性计算工具（function calling / 计算器），不让模型心算。
